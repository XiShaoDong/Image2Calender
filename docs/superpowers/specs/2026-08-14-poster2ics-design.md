# 图片批量导入苹果日历工具（poster2ics）设计文档

日期：2026-08-14
状态：已评审通过

## 1. 背景与目标

用户经常收到各种活动图片（活动海报、聊天截图、网页截图），需要将其中包含的活动信息（标题、日期、时间、地点）批量导入苹果日历。

**核心诉求：**
- 网页服务：浏览器（手机/电脑）上传多张图片
- 自动 OCR 识别文字（中英文混合）
- 提取活动信息：标题、日期、时间、地点
- 先预览确认（可编辑）再生成日历，避免识别错误直接进日历
- 批量：一次上传多张图，合并生成一个 .ics 文件，手机一键导入
- 先本地运行（后续可部署云端），OCR 用免费 API

## 2. 技术选型

- **方案 A：Python FastAPI + 单页原生 HTML 前端**
- OCR：OCR.space 免费 API（25,000 次/月，500 次/天；本工具月用量 <500 张，足够）
- 解析：纯正则规则，零成本，不依赖 LLM
- 日历格式：标准 iCalendar (.ics)，多事件合并单文件

## 3. 架构与数据流

```
浏览器(手机/电脑)                   本地后端 (FastAPI)
┌──────────────────┐  上传多张图  ┌─────────────────────┐
│ 拖拽/选择多张图片 │ ──────────▶ │ 1. OCR 服务(ocr.py) │──▶ OCR.space 免费 API
│ 预览编辑卡片     │             │ 2. 规则解析(parser)  │
│ 勾选要导入的事件 │             │ 3. 生成 .ics        │
└──────────────────┘ ◀────────── └─────────────────────┘
   下载一个合并的 events.ics → 传到 iPhone → 点开 → 一键加入苹果日历
```

### 模块划分（后端 3 个独立模块）

| 模块 | 职责 | 接口 |
|---|---|---|
| `ocr.py` | 调 OCR.space API，返回每张图的中英混合文本 | `ocr_image(file) -> str` |
| `parser.py` | 纯正则规则解析文本 → 事件字段 | `parse_event(text, base_date) -> Event` |
| `ics_builder.py` | 将多个 Event 合并生成 .ics 文件内容 | `build_ics(events) -> str` |

前端为单页 `static/index.html`，原生 JS，无构建工具。

## 4. OCR 服务（ocr.py）

- 调 OCR.space `https://api.ocr.space/parse/image`，POST multipart
- 参数：`language=auto`（自动识别中英）、`OCREngine=1`（中文支持好、快）、`isOverlayRequired=true`（需要字体坐标用于标题识别）、`scale=true`（提升低清海报识别率）
- 免费版单图限 1MB：前端上传前先用 canvas 压缩到 1MB 内
- API key 获取方式（二选一，key 优先）：
  1. 环境变量 `OCRSPACE_KEY`
  2. 网页设置框粘贴，保存到本地 `config.json`
- 每天 500 次上限：后端记录当日用量，超限时返回友好错误提示

## 5. 规则解析（parser.py）

纯正则，零成本。识别字段：

- **日期**：`8月15日`、`8月15号`、`8月15`、`2026/8/15`、`2026-8-15`、`Aug 15`、`15 Aug 2026`、`下周五`、`本周六` 等
  - 支持中英文月份（8月 / August / Aug）
  - 相对日期：今天/明天/后天/本周X/下周X
- **时间**：`19:00`、`19:00-21:00`、`19:00~21:00`、`7:00PM`、`7pm`、`晚上7点`、`下午3点半` 等
  - 时段（上午/下午/晚上/中午）自动转换 12/24 小时制
- **标题**：利用 OCR.space 返回的字体高度坐标，取最大字号文本行；识别不到则取文本第一行
- **地点**：包含 `地点`、`地址`、`venue`、`@` 关键词的行
- **年份推断**：图上无年份 → 当前年；若日期已过 → 推断明年
- **时长**：给了结束时间用区间；否则默认 2 小时
- **描述**：OCR 原文整段放入事件描述，便于核对

解析结果带置信度标记：日期/时间解析失败 → 前端标红必填提醒；解析到多个候选日期 → 黄色警告让用户确认。

## 6. 日历生成（ics_builder.py）

- 标准 iCalendar 格式：`BEGIN:VCALENDAR` / `VEVENT` 块，`UID`、`DTSTART`、`DTEND`、`SUMMARY`、`LOCATION`、`DESCRIPTION`
- 时区：使用本地时区（Asia/Shanghai），写入 `TZID`
- 多事件合并为一个 .ics 文件

## 7. 前端（static/index.html）

- 多图拖拽/选择上传，逐张显示处理状态
- 每张图一张卡片：识别出的 标题/开始时间/结束时间/地点/描述，全部可编辑；附原图缩略图
- 解析失败字段标红；日期缺失的卡片不能勾选
- 多个候选日期黄色警告
- 勾选卡片 → 「生成日历文件」→ 下载 `events.ics`
- 页面含手机导入步骤说明（AirDrop/微信传至 iPhone → 点开 .ics → 添加日历）
- 设置区：粘贴 OCR.space API key（可留空用环境变量）

## 8. API 设计

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 前端页面 |
| POST | `/api/ocr` | multipart 多图上传，返回每张图解析后的事件字段（JSON） |
| POST | `/api/ics` | 提交用户确认后的事件列表，返回 .ics 文件内容（下载） |
| GET/POST | `/api/config` | 读写 API key |

## 9. 错误处理

- OCR 失败（超限/网络/格式不支持）→ 卡片显示原始文本，允许手动填写字段
- 解析出可疑结果 → 黄色警告提示确认
- OCR.space 每日 500 次上限 → 后端计数并提示次日再试
- 无日期的事件禁止生成

## 10. 测试

- `pytest` 单元测试覆盖 parser：中英文日期、时间各种格式用例（几十种）、年份推断、时段转换、标题/地点识别
- 手测：生成中文、英文测试海报各一张，走完整上传→识别→预览→生成→（模拟）导入流程
